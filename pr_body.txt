**Vulnerability:**
Command injection vulnerability in `.github/workflows/publish-binaries.yml` where untrusted user input via `inputs.tag_name`, `github.event.release.tag_name`, or `github.ref_name` was directly interpolated into a bash run step.

**Risk & Impact:**
An attacker with permission to trigger the workflow (e.g., by creating a release or dispatching with malicious tag inputs) could execute arbitrary shell commands in the context of the GitHub Actions runner. This could potentially lead to secrets exposure (such as the `GITHUB_TOKEN` used in the deployment step) and unauthorized access or modification to the repository's assets.

**Remediation:**
Extracted the untrusted variables (`inputs.tag_name`, `github.event.release.tag_name`, `github.ref_name`) from the inline `${{ ... }}` syntax and mapped them directly into a `TAG_INPUT` environment variable using an `env` block. The bash script then securely reads this value from `$TAG_INPUT`, removing the risk of string interpolation and escaping issues.

**Verification:**
- Verified that the syntax of the modified GitHub Actions workflow is valid.
- Simulated the workflow environment locally using `make configure build run` under `xvfb-run` to ensure no related build regressions were introduced.
